# Регламент технического обслуживания

## Периодичность
- Проверять запуск и преобразование перед демонстрацией или сдачей.
- Проверять `logs/app.log` при ошибках и после тестирования.
- Создавать резервную копию перед изменением таблицы.
- Запускать автотесты после изменения кода.
- Проверять восстановление после изменений механизма резервирования.

## Запуск и проверка
1. Убедиться, что установлен Python 3.10+.
2. Из корня проекта запустить `python converter_tkinter.py`.
3. Проверить `10` в основании `2` → `1010`.
4. Проверить `255` в основании `16` → `FF`.
5. Убедиться, что в `logs/app.log` появились записи.

## Резервное копирование
1. Запустить приложение и нажать «Создать резервную копию».
2. Проверить появление JSON-файла в `backups/`.
3. Перед крупными изменениями хранить копию также на отдельном носителе.

## Восстановление
1. Выбрать нужную JSON-копию в интерфейсе.
2. Подтвердить замену текущей таблицы.
3. После восстановления выполнить тестовый перевод.
4. Если восстановление не работает, проверить JSON и права записи в `data/`.

## Диагностика
- Не запускается: проверить версию Python и текст ошибки в терминале.
- Нет журнала: проверить права записи в папку проекта и `logs/app.log`.
- Ошибка сохранения: проверить права доступа и свободное место.
- Не читается копия: выбрать другую или создать новую.
- Нет Tkinter: установить версию Python с компонентом Tcl/Tk.

После изменений запускать `python -m unittest discover -s tests -v` и проверять GUI вручную.
